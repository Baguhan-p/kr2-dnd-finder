# D&D Finder

Платформа для поиска мастеров и игроков настольных ролевых игр: D&D 5e, Pathfinder, Call of Cthulhu, Savage Worlds, Shadowrun, Cyberpunk RED.

- **Опубликованная версия:** https://baguhan-p.github.io/kr2-dnd-finder/index.html
- **Репозиторий:** https://github.com/Baguhan-p/kr2-dnd-finder

## Описание проекта

Многостраничный интерфейс сервиса, который соединяет мастеров и игроков для настольных ролевых игр. Реализованы каталоги анкет с фильтрами, сортировкой и постраничным просмотром, заявки на поиск участников с бронированием мест, публичные профили с рейтингом и отзывами, глобальный поиск, личный кабинет, избранное, встроенный режим броска кубиков, FAQ и служба поддержки.

### Функциональные возможности

- каталоги мастеров и игроков: фильтр по системам, формату, городу и опыту; сортировка по рейтингу, опыту и имени; пагинация по 6 карточек;
- заявки «мастер ищет игроков» и «игрок ищет мастера» объединены с анкетами на страницах разделов через вкладки;
- страница заявки: таблица характеристик, список участников, комментарии, бронирование места с подтверждением;
- публичный профиль: вкладки «Обзор / Отзывы / Активные заявки», рейтинг в виде кубика d20, кнопка «Связаться»;
- публикация собственной заявки через модальное окно с валидацией;
- глобальный поиск по анкетам и заявкам с фильтрами по типу, системе, формату и городу;
- личный кабинет: редактирование профиля с живым превью, загрузка аватара, список своих заявок;
- избранное: сохранение мастеров и игроков, счётчик в шапке, отдельная страница;
- режим броска кубиков: d4–d100, количество, модификатор, история бросков, подсветка нат-20 и нат-1;
- переключатель анимаций с сохранением выбора;
- FAQ и форма обратной связи с валидацией.

## Используемый фреймворк

**Bootstrap 5.3.3** — CSS-фреймворк с 12-колоночной сеткой, готовыми компонентами и utility-классами.

Выбор обусловлен требованиями методических указаний: понятная сетка `container / row / col-*`, готовые адаптивные классы, встроенные JS-компоненты (`modal`, `accordion`, `carousel`, `nav-tabs`, `toast`), подробная документация. Альтернативы (Tailwind CSS, Bulma) не использовались: Tailwind строится на utility-классах без готовых компонентов, Bulma не содержит JavaScript-поведения, необходимого для модальных окон и раскрывающейся навигации.

## Способ подключения Bootstrap

Bootstrap подключён **через CDN** (jsDelivr). Собственный файл `css/custom.css` подключается **после** Bootstrap, чтобы переопределять стили фреймворка каскадом.

В `<head>` каждой страницы:

```html
<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">
<link rel="stylesheet" href="css/custom.css">
```

Перед `</body>`:

```html
<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>
```

JS Bundle необходим для работы `navbar` (мобильное меню), `modal`, `accordion`, `carousel`, `nav-tabs`, `toast`.

Порядок подключения собственных скриптов:

```html
<script src="js/motion.js"></script>   <!-- в <head>, выставляет режим анимаций до отрисовки -->
...
<script src="js/data.js"></script>     <!-- данные и хелперы -->
<script src="js/layout.js"></script>   <!-- шапка, подвал, модальные окна, toast -->
<script src="js/catalog.js"></script>  <!-- движок каталога и карточки -->
<script src="js/main.js"></script>     <!-- общая логика -->
<script src="js/smoke.js"></script>    <!-- только на главной -->
```

## Сетка и адаптивность

Используется 12-колоночная сетка Bootstrap: `container` → `row` → `col-*`. Промежутки задаются классами `g-2`, `g-3`, `g-4`.

| Блок | Классы колонок | Поведение |
|---|---|---|
| Карточки каталога | `col-12 col-md-6 col-lg-4` | 1 / 2 / 3 карточки в ряд |
| Преимущества главной | `col-12 col-md-6 col-lg-3` | 1 / 2 / 4 блока в ряд |
| Каталог и фильтры | `col-12 col-lg-3` + `col-12 col-lg-9` | сайдбар и сетка на десктопе, столбец на мобильном |
| Страница заявки | `col-12 col-lg-8` + `col-12 col-lg-4` | контент и карточка автора |
| Личный кабинет | `col-12 col-lg-5` + `col-12 col-lg-7` | форма и превью |
| Подвал | `col-12 col-md-4` ×3 | бренд слева, разделы по центру, контакты справа |
| Поля форм | `row g-3` + `col-12 col-md-6` | два поля в ряд на десктопе |

Дополнительно:
- `navbar-expand-lg` сворачивает меню в бургер ниже 992px;
- sticky-фильтры отключаются медиазапросом `@media (max-width: 991px)`;
- таблица характеристик обёрнута в `table-responsive`;
- выравнивание подвала меняется через `text-center text-md-start` / `text-md-end`.

Проверенные ширины: **375px, 768px, 1024px, 1440px**.

## Темизация через CSS-переменные Bootstrap

Фэнтезийное оформление получено не заменой компонентов, а переопределением переменных темы фреймворка в `:root` файла `css/custom.css`:

```css
:root {
  --bs-primary: #c9a227;          /* золото вместо синего */
  --bs-body-bg: #140d1f;          /* тёмный фон */
  --bs-body-color: #e9dfc9;
  --bs-card-bg: #f1e6cd;          /* пергаментные карточки */
  --bs-modal-bg: #f1e6cd;
  --bs-table-striped-bg: #e7d9b8;
  --bs-accordion-active-bg: #241733;
  --bs-info-bg-subtle: rgba(91,134,168,0.18);
}
```

За счёт этого перекрашиваются все компоненты сразу: кнопки, бейджи, алерты, таблицы, аккордеон, модальные окна, формы. Собственный CSS дополняет фреймворк (шрифты Cinzel / Spectral, фактуры пергамента, сургучные аватары, декоративные псевдоэлементы, анимации), а не заменяет его.

## Хранение данных

Бэкенд не используется. Данные анкет и заявок хранятся в `js/data.js`, пользовательское состояние — в `localStorage`:

| Ключ | Содержимое |
|---|---|
| `dndFavorites` | список избранных анкет в формате `master:id` / `player:id` |
| `dndMyProfile` | профиль пользователя из личного кабинета (включая аватар в base64) |
| `customMasterRequests` | заявки мастеров, созданные через модальное окно |
| `customPlayerRequests` | заявки игроков, созданные через модальное окно |
| `dndMotion` | состояние переключателя анимаций (`on` / `off`) |

При загрузке `data.js` подмешивает пользовательские заявки в общие массивы, поэтому они участвуют в фильтрации, сортировке, поиске и открываются на странице заявки.

## Самостоятельные доработки

1. **Расширение набора страниц с 4 до 9.** Добавлены `masters.html`, `players.html`, `request.html`, `profile.html`, `search.html`, `support.html`, `favorites.html`, `account.html` — собственные разделы и сценарии сверх базовой структуры.

2. **Единый layout через JavaScript.** Шапка, подвал, четыре модальных окна, контейнер toast и плавающая кнопка кубиков инжектятся файлом `js/layout.js` на всех страницах; активный пункт меню определяется автоматически по URL. Устранено дублирование навигации и обеспечена визуальная целостность.

3. **Динамический рендеринг из базы данных.** Все карточки, профили, заявки и результаты поиска строятся через DOM API из `js/data.js`, а не копируются в HTML вручную.

4. **Переиспользуемый движок каталога.** Один файл `js/catalog.js` обслуживает четыре типа каталога по атрибуту `data-catalog` на `<body>`: собирает нужный набор карточек, фильтров и вариантов сортировки.

5. **Рабочие фильтры, сортировка и пагинация.** Фильтр по системам (чекбоксы), формату, городу и опыту; для заявок — по системе, формату и свободным местам. Сортировка по рейтингу, опыту, имени, времени, свободным местам. Постраничный просмотр по 6 карточек с счётчиком найденного.

6. **Объединение анкет и заявок через `nav-tabs`.** Заявки мастеров и игроков живут внутри соответствующих разделов с переключением источника данных без перезагрузки; переход по `#requests` сразу открывает вкладку заявок.

7. **Глобальный поиск.** Страница `search.html` ищет одновременно по мастерам, игрокам и обоим типам заявок с фильтрами по типу, системе, формату и городу; вход — кнопками «Поиск мастеров» / «Поиск игроков» из разделов, поиск предзаполняется через GET-параметры.

8. **Интерактивный сценарий заявки.** Бронирование места и отклик проходят через `modal` с подтверждением и `toast`; комментарий добавляется в DOM без перезагрузки; заполненность мест показана цветным `badge`.

9. **Публикация заявки через модальное окно.** Форма с переключением полей по типу заявки, встроенной валидацией Bootstrap (`was-validated` + `invalid-feedback`) и сохранением в `localStorage` — новая запись сразу попадает в каталог и переживает перезагрузку.

10. **Публичный профиль с вкладками.** `nav-tabs` «Обзор / Отзывы / Активные заявки», рейтинг в виде тематического кубика d20 (SVG), список активных заявок со ссылками, кнопка «Связаться» через `modal`.

11. **Личный кабинет.** Редактирование профиля с живым превью карточки, загрузка аватара через `FileReader` с ограничением размера, список собственных заявок; имя автоподставляется в форму публикации заявки.

12. **Избранное.** Кнопки-сердечки на карточках, счётчик `badge rounded-pill` в шапке, отдельная страница с сетками мастеров и игроков, хранение в `localStorage`, удаление прямо из избранного.

13. **Режим броска кубиков.** Плавающая кнопка открывает `modal` с выбором d4–d100 через `btn-group`, количеством и модификатором, анимацией прокрутки результата, подсветкой критического успеха (нат-20) и провала (нат-1), историей последних бросков в `list-group`.

14. **Анимации появления и исчезновения.** Система на `IntersectionObserver` + `MutationObserver`: карточки, плитки, аккордеоны и заголовки материализуются каскадом при входе в экран и растворяются при уходе; работает и для динамически отрисованного контента. Смена фильтра, сортировки, страницы или вкладки плавно гасит старый набор и проявляет новый.

15. **Canvas-эффект дыма на главной.** Фиолетовые клубы и золотые искры поднимаются снизу вверх, покачиваются и растворяются; один `requestAnimationFrame`-цикл, ограничение DPR, пауза при скрытой вкладке.

16. **Переключатель анимаций.** Кнопка в шапке включает и выключает все эффекты, состояние хранится в `localStorage` и действует на всех страницах через атрибут `data-motion` на `<html>`; событие `motionchange` останавливает и возобновляет дым и заново проявляет элементы.

17. **Фэнтезийная тема без замены компонентов.** Палитра, фоны карточек, модалок, таблиц и аккордеона заданы переопределением переменных `--bs-*`, включая `--bs-*-bg-subtle` для алертов; добавлены тематические шрифты, фактуры и декоративные элементы.

18. **Публикация через GitHub Pages.** Проект доступен по постоянной ссылке, указанной в начале документа.

## Способы проверки проекта

1. **Главная.** Открыть `index.html`: работает carousel-герой с тремя слайдами, четыре блока новых анкет и заявок, блок преимуществ, дым поднимается снизу вверх, разделители и подвал отображаются корректно.

2. **Навигация.** В шапке четыре пункта (Главная, Мастера, Игроки, Поддержка) и три иконки: избранное со счётчиком, личный кабинет, переключатель анимаций. Активный пункт подсвечен. Ниже 992px меню сворачивается в бургер и раскрывается по нажатию.

3. **Каталог мастеров.** Открыть `masters.html`: применить фильтр по системе, формату, городу и опыту — счётчик «Найдено» и сетка перестраиваются, старый набор карточек плавно гаснет. Сменить сортировку, пролистать пагинацию, нажать «Сбросить».

4. **Вкладки заявок.** Переключиться на «Заявки мастеров» — набор данных, фильтры и варианты сортировки меняются без перезагрузки. Ссылка «Заявки мастеров» из подвала открывает раздел сразу на этой вкладке. То же проверить на `players.html`.

5. **Страница заявки.** Кликнуть «Открыть заявку»: таблица характеристик, список участников со ссылками на профили, комментарии. Нажать «Зарезервировать место» → модальное окно подтверждения → toast. Добавить комментарий — он появляется без перезагрузки. Для заявки без свободных мест кнопка заблокирована.

6. **Профиль.** Кликнуть «Профиль» на карточке: переключить вкладки «Обзор / Отзывы / Активные заявки», проверить рейтинг d20 и переходы по активным заявкам. Нажать «Связаться» → модальное окно с формой.

7. **Публикация заявки.** На `masters.html` нажать «+ Подать заявку», отправить пустую форму — сработает валидация Bootstrap с подсказками. Заполнить и опубликовать — заявка появится во вкладке заявок, сохранится после `F5` и откроется на странице заявки.

8. **Поиск.** Нажать «Поиск мастеров» — откроется `search.html` с предвыбранным типом. Проверить поиск по ключевому слову и фильтрам по системе, формату и городу; убедиться, что находятся и анкеты, и заявки.

9. **Избранное.** Нажать сердечко на карточке — иконка меняется, появляется toast, счётчик в шапке растёт. Открыть `favorites.html` — обе сетки заполнены. Удалить из избранного прямо на странице — карточка исчезает, счётчик уменьшается. Перезагрузить — состояние сохранилось.

10. **Личный кабинет.** Открыть `account.html`, изменить имя — превью обновляется на лету. Загрузить изображение до 300 КБ — аватар встаёт в круг. Сохранить профиль, затем открыть форму заявки — имя подставлено автоматически.

11. **Кубики.** Нажать плавающую кнопку 🎲 слева внизу: выбрать d20, задать количество и модификатор, бросить — числа прокручиваются, результат подсвечивается при нат-20 и нат-1, история пополняется.

12. **Переключатель анимаций.** Нажать ✨ в шапке — иконка меняется на 💤, дым исчезает, анимации отключаются. Повторный клик возвращает эффекты с каскадным проявлением. Перезагрузить страницу — выбор сохранён.

13. **Поддержка и FAQ.** Открыть `support.html`: отправить форму с пустыми полями — сработает валидация; заполнить корректно — появится toast. Раскрыть и свернуть блоки FAQ (accordion).

14. **Адаптивность.** В DevTools проверить ширины 375 / 768 / 1024 / 1440px: сетка не выходит за границы, карточки перестраиваются по 1 / 2 / 3, меню сворачивается, sticky-фильтры отключаются на мобильных, таблица заявки прокручивается горизонтально, модальные окна помещаются на экране.

15. **Консоль.** Убедиться в отсутствии ошибок JavaScript и ошибок подключения Bootstrap на всех страницах.

## Запуск локально
